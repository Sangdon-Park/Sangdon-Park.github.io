이제 실제로 채웁니다. 왼쪽 그림이 Cline 설정 화면의 구성도이고, 오른쪽 다섯 단계 순서대로 갑니다. 실제 화면은 확장을 설치한 여러분 VS Code 안에서만 보여서 구성도로 그렸고, 항목 이름은 Cline 공식 문서와 Z.ai 공식 문서에 나온 그대로입니다.

1번. Cline 패널 오른쪽 위 톱니바퀴를 누릅니다. 아까 Gemini 설정할 때 들어갔던 그 화면입니다.

2번. API Provider 드롭다운을 'OpenAI Compatible'로 바꿉니다. 'OpenAI'가 아니라 뒤에 'Compatible', 호환이 붙은 것입니다. 이름에 OpenAI가 들어가서 헷갈리는데, 이건 'OpenAI 방식으로 말하는 서버라면 무엇이든'이라는 뜻이고, 우리는 그 자리에 Z.ai 주소를 넣을 겁니다. 목록에 'Z AI'라는 제공자도 따로 보이는데 그건 고르지 마세요. 그 제공자는 Z.ai의 일반 과금 주소로 요청을 보내서 우리 구독 키로는 '1113 Insufficient balance' 오류가 나고, 모델 목록도 glm-5.2까지만 있어서 5.3을 고를 수 없습니다. 제가 직접 확인한 내용입니다.

3번. Base URL 칸에 https://api.z.ai/api/coding/paas/v4 를 넣습니다. 한 글자라도 틀리면 연결이 안 되니 직접 치지 말고 제가 올려 드린 글에서 복사해 붙이세요. 끝에 슬래시를 더 붙이거나 앞뒤에 공백이 들어가지 않게 주의.

4번. API Key 칸에 수업 공용 키를 붙여넣습니다. 키는 수업 시간에 따로 알려 드립니다. Gemini 키와 마찬가지로 앞뒤 공백이나 줄바꿈이 섞이지 않게.

5번. Model 칸은 목록에서 고르는 게 아니라 직접 쳐 넣습니다. glm-5.3 이라고 소문자로 정확히. 그리고 바로 아래 Model Configuration을 펼쳐서 'Supports Images' 체크를 끕니다. 이 모델은 글만 받는 모델이라 이미지 지원을 켜 두면 Cline이 엉뚱한 요청을 보낼 수 있어서, Z.ai 공식 문서가 끄라고 안내하는 항목입니다. 다 됐으면 Done, 그리고 채팅창에 '안녕'을 보내 봅니다. 응답이 오면 연결 성공입니다. Gemini 때처럼요.

아래 상자는 안 될 때입니다. 'Rate limit reached'나 1302가 보이면 동시에 여러 명이 눌러서 줄을 선 것이니 기다리면 됩니다. Cline이 알아서 재시도합니다. 401이나 'Invalid API key' 같은 키 오류면 키를 다시 복사해 붙이고, Base URL도 다시 확인하세요. 그래도 계속 막히면 API Provider를 Google Gemini로 되돌리면 아까 넣어 둔 내 키가 그대로 있어서 바로 계속할 수 있습니다. 두 엔진을 다 갖춘 사람이 오늘 체크리스트를 통과하는 겁니다.
